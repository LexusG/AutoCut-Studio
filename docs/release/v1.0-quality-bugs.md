# AutoCut Studio v1.0 — Quality and Release Defects

Defects found during release-candidate validation of `1.0.0-rc.1`.

Severity follows the release rules: **P0** critical (data loss, corruption, security, will not
launch), **P1** release blocker, **P2** important, **P3** minor.

**No v1.0 release while any P0 or P1 remains open.**

---

## P0 — Critical

None found.

---

## P1 — Release blockers

### REL-001 — Primary Auto workflow does not exist
**Status:** OPEN · **Cause:** Phase 11 Milestone 5 was never implemented.

The intended v1.0 workflow is *New Auto Edit → Import → Platform → Style → Music → Generate
Versions → Favorite → Export*. The application has no "New Auto Edit" entry point, no automatic
multi-version generation, no Favorite, and no Recommended ranking. The "Generate Versions" control
that exists is the Phase 8 output-variants panel, which re-frames the **same** edit for different
platforms rather than producing different edits.

**Effect:** the product's headline capability is absent. Test-plan sections covering multi-version
generation, version differentiation and recommendation are untestable.

### REL-002 — Automatic edit quality does not meet the product goal
**Status:** OPEN · **Cause:** Phase 11 Milestones 2–4 were never implemented.

Observed in the packaged RC: a three-clip project produced three segments of identical length with
one transition type throughout, in a content-blind order.

- `arrangeSources` orders clips by orientation → has-audio → longest-first. No content signal.
- `distribute()` allocates duration as a uniform equal share, so every clip gets the same length.
- One transition type is applied to every boundary.
- There is no hook selection, ending selection, shot-diversity scoring, music-energy awareness,
  motion effect, visual-consistency pass or pre-preview quality review.

**Effect:** output is a uniformly-paced concatenation, not a professionally-paced edit. The
"would I post this?" standard cannot be met by construction.

### REL-003 — No in-app learning system
**Status:** OPEN · **Cause:** Phase 12 produced requirements only.

No Tutorial Center, Quick Tour, first-run offer, contextual help, tutorial search or Help menu.
This is the v1.0 bar set in `docs/phase-12-requirements.md`.

### REL-004 — GPLv3 FFmpeg redistributed by an MIT project
**Status:** OPEN · **Severity:** P1 for distribution.

The bundled FFmpeg is built `--enable-gpl --enable-version3` with libx264, libx265, libvidstab and
others, making it GPLv3. The AppImage and `.deb` ship it with no licence text and no source offer.
Options and analysis are recorded in `THIRD_PARTY_NOTICES.md`. No option has been chosen.

## P2 — Important

### REL-005 — Deferred production capability absent
**Status:** OPEN · **Cause:** Phase 10 Milestones 2–5 never implemented.

Portable projects, media relink, proxy media, render queue, storage manager, project templates,
export recipes and hardware-encoder detection do not exist. Test-plan sections covering them are
untestable.

### REL-006 — No About screen; version not surfaced
**Status:** OPEN. The application version is not shown anywhere in the UI.

### REL-008 — e2e regression suite was broken and unnoticed
**Status:** FIXED in this branch.

Adding the **Save Project As** button in Phase 10 made `getByRole('button', { name: 'Save
Project' })` ambiguous, breaking six call sites across three specs. Schema assertions were also
pinned to `version: 8` and broke at v10. Neither was noticed because **Playwright is not run in
CI** — CI runs typecheck, unit tests and build only.

**Fix:** selectors made exact; schema assertion no longer pins a version number.
**Follow-up:** add Playwright to CI, or the same class of breakage recurs.

### REL-015 — Phase 6/7/8 e2e specs do not complete in this environment
**Status:** OPEN · **Severity:** P2 (test suite, not a demonstrated product defect).

After fixing REL-008 the three long-form specs still fail, all at the same point: the Edit Plan
overlay never appears after **Create Edit Plan**, even with the wait raised to 600 s.

This is **not** reproducible against the product. Two independent checks were run:

- The packaged release candidate completed the full workflow — plan, preview and a verified
  1080×1920 export — using classic selection.
- A diagnostic reproducing the Phase 6 configuration exactly (8 clips built from the same
  `two-people-studio.png` fixture with `flite` speech, smart selection, `fast` analysis quality,
  balanced content awareness, Prefer People and Prefer Spoken Moments) produced a plan in **20
  seconds**, with person detection progressing normally to "Clip 8 of 8".

So the pipeline these specs exercise is healthy, and the fault lies in the specs themselves or in
their fixture setup. Root cause is not isolated.

**Effect on this release:** Phase 1–9 regression **could not be certified**. The suite needs
maintenance before it can serve as a release gate, and it should then be added to CI (see REL-008)
so it cannot silently rot again.

### REL-010 — Import errors exposed internal binary paths
**Status:** FIXED in this branch.

Importing a corrupt file produced a user-visible summary reading
`corrupt.mp4: /…/runtime/linux-x64/ffprobe/ffprobe exited with code 1.` — the absolute path of a
bundled binary and a process exit code, in the always-visible line.

**Fix:** `failureFor` and `errorResult` now produce a plain-language message and move the raw
process output into the expandable details, where the pattern already existed. Verified in the
repackaged candidate: the visible line now reads *"This file could not be read as video. It may be
corrupt or in an unsupported format."*

### REL-011 — Production CSP allowed `ws:` and `http:`
**Status:** FIXED in this branch.

`connect-src` included `ws:` and `http:` for the Vite dev server, and shipped unchanged to
production. Defence in depth rather than a reachable hole — the renderer is sandboxed with no Node
integration and `script-src` is restricted — but unnecessary in a packaged build.

**Fix:** a build-only Vite plugin strips both from the production CSP. Verified: production output
is `connect-src 'self' autocut-asset:`; the dev source is unchanged.

### REL-012 — Default Electron icon ships as the application icon
**Status:** OPEN. `electron-builder` reports *"default Electron icon is used"*. The `.deb` installs
Electron's generic icon at every size. `.desktop` metadata is otherwise correct.

### REL-013 — `desktopName` not set
**Status:** OPEN. `electron-builder` warns that without `desktopName` and `linux.syncDesktopName`,
desktop environments may not associate running windows with the `.desktop` entry.

## P3 — Minor

### REL-007 — No lint configured
**Status:** OPEN. There is no `npm run lint`. Type checking is the only static analysis.

### REL-014 — Duplicate accessible names in the UI
**Status:** OPEN. "Generate Preview" exists in both the editor header and the Edit Plan footer;
the Local AI gear button uses the same name on two screens; the Content button's visible label is
`Content` while its `aria-label` is `Transcript`. This already caused REL-008 and will complicate
the tutorial targeting specified for Phase 12.

## Automatic-quality observations

Recorded against the RC using synthetic clips. **These are mechanism observations, not
publishability judgements** — no real footage was available, so the product-quality question in
the test plan is unanswered.

| ID | Observation | Root cause |
| --- | --- | --- |
| AUTO-QUALITY-001 | Every segment received an identical duration | Uniform equal-share allocation in `distribute()` |
| AUTO-QUALITY-002 | Clip order is unrelated to content | `arrangeSources` sorts by orientation, audio presence and length |
| AUTO-QUALITY-003 | The same transition is applied at every boundary | Transition type is chosen once in the planner |
| AUTO-QUALITY-004 | No deliberate opening or closing shot | Hook and ending planners do not exist |

All four are consequences of REL-002 and are fixed by completing Phase 11 M2–M4, not by
adjustments here.
